Lab 2

Round-robin discussion with turn enforcement.

Goal

Build a 3-agent discussion channel. Verify that the discussion adapter enforces round-robin turn order — only the current speaker may send, and others are blocked by the hub.

What you will learn

  • How to open a multi-party channel with target=[...].
  • How DiscussionAdapter advances current_speaker round-robin.
  • How can_send gates turns and how out-of-turn sends are rejected.
  • How to close a channel explicitly and replay the transcript.
  • How view policies project history into each agent's LLM turn.

How to apply it

Use the discussion adapter for brainstorming, review boards, or any multi-party deliberation where you want fair, enforced turn-taking rather than free-form chat. The round-robin invariant prevents one agent from dominating.

Starter code

# examples/labs/lab2.py
import asyncio
from ag2 import Agent
from ag2.network import EV_TEXT, Hub
from ag2.network.testing import MemoryKnowledgeStore
from common import make_config

async def main():
    config = make_config()
    hub = await Hub.open(MemoryKnowledgeStore(), ttl_sweep_interval=0)
    a = await hub.register(Agent("optimist", prompt="You are an optimist. One sentence.", config=config))
    b = await hub.register(Agent("skeptic", prompt="You are a skeptic. One sentence.", config=config))
    c = await hub.register(Agent("pragmatist", prompt="You are a pragmatist. One sentence.", config=config))
    channel = await a.open(type="discussion", target=["skeptic", "pragmatist"])
    await channel.send("Topic: should we adopt microservices?", audience=[b.agent_id, c.agent_id])
    await asyncio.sleep(20)
    await channel.close(reason="done")
    await asyncio.sleep(1)
    wal = await hub.read_wal(channel.channel_id)
    for env in wal:
        if env.event_type == EV_TEXT:
            name = "optimist" if env.sender_id == a.agent_id else ("skeptic" if env.sender_id == b.agent_id else "pragmatist")
            print(f"{name}: {env.event_data['text'][:80]}")
    await hub.close()
asyncio.run(main())

Tasks

  1. Run it. Confirm the WAL shows alternating speakers in round-robin order.
  2. Try sending from a non-current speaker manually; observe the rejection.
  3. Change the target order and observe how the round-robin order changes.
  4. Inspect hub.adapter_state(channel_id) to read current_speaker and turn_count.

Key takeaways

  • Round-robin is enforced by the hub, not by convention.
  • can_send is the public probe for turn ownership.
  • Discussion channels need an explicit close() (or TTL).
  • Each participant sees a projected view of the WAL, not the raw transcript.
